Biology 3315 Molecular Evolution and Phylogenetics

Distances

When handling biological data distance measures, also known as dissimilarity measures or dissimilarity indices, are useful in comparing multiple entities. These entities can be populations (think allele dynamics), environmental samples, gene sequences, genomes, gene expression data etc. In essence every time we draw a comparison, we ask the quantitative question how much is X similar to Y or better yet how much are X and Y dissimilar. The degree of dissimilarity between X and Y can simply be represented as percent dissimilarity or might require a more sophisticated mathematical transformation. The approach used to measure dissimilarities depends on the nature of the data, it’s format and of course the question in need of answering. For example when performing a pairwise sequence alignment the alignment score can be thought of as a relative measure of the dissimilarity between the two sequences and can be expressed as percent of the maximal alignment score.

When calculating distances between entities (e.g. populations) the data you work with can be tabulated, e.g. allele/genotype frequency/abundance table etc or non tabulated e.g. sequence alignment. R can do both and the approaches are quite similar.

Base R is equipped to handle distance calculation with tabulated data. First let’s generate data to work with, by uploading the dune data-set. Dune is a part of the vegan package and it contains the counts of 30 different plants (columns) from 20 different sites (rows). Using symmetric distances

When we calculate distances of tabulated data we are conducting a pairwise comparison of every row on the table to every other row, based on the values found in each of the columns. Rows with similar values in each column will receive a low score. The score represents distance, low score = short distance meaning that they are not very dissimilar (or very similar). In the snippet bellow I am using euclidean distance measure to calculate the distance between each of the samples. Using asymmetrical distances

Distance measures included in the dist functions are not necessarily designed to be used with biological data, since most of them are symmetric. Symmetric dissimilarity measures regard double absence similarly to double presence.

Say two populations show presence of a certain genotype or allele, dissimilarity measures will count this double presence towards lowering the dissimilarity score. Now say these populations also show an absence of a certain allele or genotype, symmetric measures will treat this as a similarity between the two populations as well. However, when it comes to biological data, the absence can come from insufficient sampling of the population rather than true absence. Therefore need to use an asymmetric measure. A measure that does not treat double absence and double presence equally.

The R package vegan contains additional asymmetric dissimilarity measures such as Bray-Curtis. One of the contributes to the package is Dr. Gavin Simpson a prof from the University of Regina, worth checking out if you are interested in ecological and environmental informatics

The snippet bellow uses the function vegdist(), the vegan implementation of the dist function, with Bray-Curtis as a dissimilarity index. The function is run twice, with binary set to either T or F. When binary is set to T all values larger than 0 are converted to 1 and the rows are evaluated based on presence and absence alone. When binary is set to F the distance factors in weight as well (i.e. not just present but how much is present). These sort of measures are important in molecular evolution but also when analyzing omics data (and ecology of course).

> dune.vd.bry <- vegdist(dune, method = "bray", binary = F)
> 
> dune.vd.bry.bin <- vegdist(dune, method = "bray", binary = T)

Two dimensional representation of distances

Distance matrices are multidimensional, and as such it becomes harder to draw meaningful conclusions from them as the number of rows in your original table increase. E.g. when working with a matrix of 3 rows and 3 columns is easier to understand compared with the one you are curtly working with which has 20rows and 20 columns.

Ordination technique such as NMDS are helpful in dimension reduction and can be used to represent the matrix in two dimensional space. We will not go into the details of ordination techniques in this course, just use them. However, in general all of them try to represent the distance matrix accurately in as fewer dimensions as possible.

The snippet bellow will use vegan’s metaMDS() function with the default setting of 2 dimensions. The end result of it will be each sample (line in the original dune data frame) receiving two coordinates representing its location in two dimensional space and how it relates to every other sample. Note that I am using the function set.seed() and you should as well, make sure to use the same seed as I so that the figures will look the same.

> #nmds for the euclidean distance matrix
> set.seed(1)
> dune.euc.nmds <- metaMDS(dune.dist.euc)
> 
> #nmds for the Bray-Curtis distance matrix
> set.seed(1)
> dune.bry.nmds <- metaMDS(dune.vd.bry)

The function metaMDS() can also call the vegdist() function and perform the distance calculation. Again, note that I am using the function set.seed() and you should as well.

> #nmds with euc
> set.seed(1)
> dune.euc.nmds2 <- metaMDS(dune, distance = "euclidean")
> 
> #nmds with bray, note binary can be set here as well
> set.seed(1)
> dune.bry.nmds2 <- metaMDS(dune, distance = "bray", binary=F)

Manipulating the output of metaMDS()

If you completed the above exercise you saw that the output of metaMDS() is essentially a list with 35 elements. What each element represents is not that important for this lab, but in general the list stores all the information needed to ensure the reproducibility of the output as well as quality measures letting you know how good is the output of metaMDS() from a statistical standpoint.

For the sake of this lab we are interested in the coordinates of each sample and these are stored in the element points. Points is a matrix with two column of coordinates (MDS1 and MDS2). Let’s extract it and turn it into a data frame.

Plotting the output of metaMDS()

The coordinates table might be simpler to look at compared to the distance matrix but it still doesn’t really help us understand which samples are more similar to one another. In order to do that we must plot the samples using a scatter plot. Samples that appear close to each other in the plot, are more similar while distant samples are less similar.

Base R’s plot function is a quick and dirty approach to generate scatter plot straight from the output list.

> plot(dune.euc.nmds$points)

As always, base graphic is very spartan and not very informative. Let’s use ggplot2 to generate a more informative plot. Note that I am using the regular expression \n inside ggtitle(), to denote a new line in the title.

> #geom_point produces a scatter plot
> p.euc <- ggplot(dune.euc.points, aes(x=MDS1, y = MDS2))+
+   geom_point(size=2)+
+   theme_bw(base_size = 16)+
+   ggtitle("NMDS Dune dataset\neuclidean distances")
> 
> p.euc
> 
> 
> p.bry <- ggplot(dune.bry.points, aes(x=MDS1, y = MDS2))+
+   geom_point(size=2)+
+   theme_bw(base_size = 16)+
+   ggtitle("NMDS Dune dataset\nBray-Curtis distances")
> 
> p.bry

Examining the two figures we can see that the two distance measures produced different configuration of the samples in two dimensional space. This was expected since we are comparing two different approaches to measuring similarities between samples. However, this does not really tell us how the configuration is different. One of the geometries of ggplot 2 is geom_text that allows for printing labels. However it requires adjustments of the coordinates to make sure that the points and labels do not overlap, which can be annoying. Luckily the ggrepel package offers additional geometries that does the dirty work for you.

> install.packages("ggrepel")
> 
> library(ggrepel)

Now, let’s use geom_text_repel() to label each point with it’s sample name and compare the output of the two measures.

> 
> p.euc2 <- ggplot(dune.euc.points, aes(x=MDS1, y = MDS2))+
+   geom_point(size=2)+
+   geom_text_repel(aes(label=Samp))+
+   theme_bw(base_size = 16)+
+   ggtitle("NMDS Dune dataset\neuclidean distances")
> 
> p.euc2
> 
> p.bry2 <- ggplot(dune.bry.points, aes(x=MDS1, y = MDS2))+
+   geom_point(size=2)+
+   geom_text_repel(aes(label=Samp))+
+   theme_bw(base_size = 16)+
+   ggtitle("NMDS Dune dataset\nBray-Curtis distances")
> 
> p.bry2

Now we have a plot we can use to compare the two distance indices. We can see that not only does each method result in a different configuration but also changes the way samples relate to each other. For example, using euclidean distances sample S1 appears to be more similar to sample 7 than sample S2 is to sample S7. However, this is not the case when using Bray-Curtis.

Dimension reduction and ordination techniques are great at visualizing the clustering of items into groups, especially if large number of samples are involved. For example, when comparing a large number of populations with respect to allele or genotype dynamics or when studying transcription or expression patterns of a large number of individuals.


A note about distances and ordination techniques

As I mentioned, distance calculation ordination techniques (and hierarchical clustering which we will deal with later in this lab) are important methods in exploring, understanding, and visualizing data. You will use these a lot as bioinformaticians and it is imperative that you choose the correct method for the data you are studying. A great resource for that is the book Numerical ecology with R. While the book deals mainly with ecological data, it is relevant to biology in general. Unfortunately, too often researches use approaches that are unsuitable for the way their data is collected or distributed. This book will help you avoid such mistakes. Dendrograms - representing distances hierarchically

BaseR has two classes of objects to house hierarchical information hclust and dendrogram. The end result of both is a dendrogram, a tree like graph where similar objects (samples, sequences, etc…) group together into clusters. Like 2D scatter plots, they are useful in fields outside evolution and phylogenetics.

hclust objects

The hclust() function performs hierarchical clustering of distance on the distance matrices you generated earlier using an assortment of aglomerative clustering algorithms. We will not go into details of each clustering algorithm at this point, but will use this to study the structure of the hclast object.

As mentioned, hierarchical clustering groups similar elements together. In the case of the dendrogram we plotted, sequences. Each vertical line in the dendrogram is referred to as a branch, each tip is referred to as a leaf (in this case, each sequence is a leaf, when you plot the dune data-set each sample will be a leaf). While the length of the branches between the two plots might be different they are read the same, sequences that branch from the same junction are more similar to each other than the rest. For example the sequence A9MLE0 and !83J28 are more similar to each other than to any other sequence. The level of dissimilarity between them is denoted by the scale of the y axis (0.2) which is the scale of the distance measure used in the clustering process, here Hamming distance. Similarly both these sequences are equally distant from A7FP80, and both are the closest sequences to it.

From the figures we can see that the sequences cluster into at least two groups (left and right). In lab 6 (maybe) and in advanced courses (e.g. all the omics courses) we will use some statistical approaches to test what is the optimal number of groups that the leafes cluster too.

A note about machine learning

While this plot might not look impressive, what you have done here is to take your first steps (unless you’ve done this before) in machine learning. When you ask an algorithm (e.g. k-means clustering) to classify your samples into groups, without specifying groups, you are performing an unsupervised machine learning. Once you have enough information about how the particular set of data classifies, you can use it to develop a predictive algorithm that would classify new samples into groups based on the information resulting from the unsupervised learning. When you train or use an algorithm to predict which category a sample would be classified to you are performing supervised machine learning.


Phylogenetic trees

Phylogenetic trees are tree like graphs that not only denote relationship between each leaf on the x axis, but also include a time component on the y axis (i.e. junctions lower on the tree are assumed to have occurred earlier than those showing upper on the tree). Phylogenetic trees require to store more information than dendrogram (e.g. information about taxa, molecular information, genetic codes, model assumptions etc). The package ape offers the class phylo which stores phylogenetic trees.

There are many methods to generate pylogenetic trees and several file formats in which phylogenetic trees are written ( nexus, newick are the most common file formats ), we will go over those during lab 7. However at the end of the day they all result in a phylo or phylo like classes of variables. Here we will only get familiarized with said class.

Because all tree like objects in R are stored as lists, it is easy to convert between them. The snippet bellow uses the as.phylo command to generate a phylo object

> hcp <- ape::as.phylo(hc)
> hcp

Class phylo

As you found out, hcp contains 4 elements. The matrix edge consists of two columns

     [,1] [,2]
[1,]   16   17
[2,]   17    1
[3,]   17   20
[4,]   20   21
[5,]   21    2
[6,]   21   28

Each row in the matrix represent a branch or an edge, if this sounds like terminology from graph theory you are correct. Indeed ape treats trees almost like association networks and actually allows you to add columns to the edge matrix and plot a network.

The numeric vector edge length contains the length of each branch of the tree

[1] 0.06032113 0.37821438 0.01798655 0.14418781 0.21604002 0.03878098

It’s order corresponds to the order of rows in the edge matrix.

The character vector tip.label surprisingly contains the label of each leaf of the tree, making those easy to modify (for example remove the UniRef90_ tag).

Nnode represents the number of nodes in the tree again this is terminology borrowed from graph theory and represents each branching point along the tree (in our case 14).

As I mentioned phylo class objects can contain additional information about the tree. Additional elements include:

  • node.label a character vector that contains node labels for example bootstrap values.

  • root.edge a numeric value giving the length of the branch at the root if it exists

  • tip.data a vector dating the tips (leaves) of the tree, useful if some are not current
