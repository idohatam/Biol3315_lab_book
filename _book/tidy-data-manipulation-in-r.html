(Tidy) Data manipulation in R

R has some powerful tools allowing you to manipulate and modify data. We have already gone over some of them. For example, you have learned several ways to subset objects, you have learned that almost any data type in R can be coerced to any other using the as.x functions. You have also learned the rbind() and cbind() can bind vectors to matrices and matrices to larger matrices.

This section of the lab will expand your capabilities of modifying data, and will focus of tools mainly from the two Tidyverse packaged, dplyr and tidyr. This packages are designed to streamline data manipulation, making data more tidy. They share some of the philosophy and framework of SQL, and thus are worth getting to know.

A tidy re-imagining of the data frame

As mentioned, the tidyverse is an assortment of packages designed for tidying up and streamlining data analysis and code writing in R. As you will see the tidyverse redesigned several basic consents in R, including data structure such as factors (via the forcats package) and data frames via the tibble package. Tibbles are the default format of tabulated data for many tidyverse packages. What are tibbles? Tibbles are first and foremost data frames. Lets see an example using readr’s read_csv() function. When importing a csv file using read_csv() we get a tibble, rather than a data frame.

Even the tidyverse can get messy sometimes

A guiding principle of tidy data is that every line of tabulated information should have a unique identifier (similar to SQL). In base R the row names act as a unique identifier for each row, as every row has a unique value. However, as you already know, base R’s approach allows you to store metadata (descriptive information about your data) in your row names as well. For example, the row name from df1 you generated by importing the file practice2.csv has site names as row names. This is a very convenient way to store data since it allows you for example to have all of your column as numeric, which means that you can do mathematical operations on all of them without having to subset the non-numeric meta data columns.

So where’s the problem? The problem is the inconsistency of the tidyverse when it comes to row names. Whille it doesn’t encourage the use of row names, it still allows it but then some tidyverse functions (e.g. filter()) will discard info from the row names and some (e.g. select()) will not. This is something to be mindful of when using tidyverse packages and functions. As a general it is best to get the row names to be a column so that you don’t lose it.

Streamlining data manipulation using %>% (pip)operator

So far we have gone through two ways of sequentially running through functions.

  1. Line by line

  2. Chaining functions using brackets eg:

X <- f3(f2(f1(x))) where the order in which the function run is inside out, i.e. f1(x) f2(output of f1),

This sort of writing, while concise, makes the code hard to read. The Tidyverse employs a piping operator %>%, colloquially referred to as an “and then” operator

x %>% f1() is equivalent to f1(x) and x %>% f1(y) is the equivalent of f1(x,y) where y is an argument of f1(). This allows the user to chain functions from left to right on a variable that was specified at the left hand side of the pipe. As a bonus, now that you understand piping I included a way to subset a culumn using %>% and $.

> #these lines are equivalent
> 
> da.df3 <- select(da.df2, 11:15)
> 
> da.df3 <- da.df2 %>% select(11:15)
> 
> #bonus subseting the species13 column with a pipe, note that the dot (.) is a place holder for 
> #the data frame at the beginning of the pipe
> df.df2.s13 <- da.df2 %>% .$species13

The piping operator can be used to chain functions sequentially, from left to right allowing for a more readable code. The snippet below will take da.df2 select column 1 and 5-13, use filter() to only keep the rows where species 11 is represented with more than 50 individuals and log transform all the numeric columns remaining after select() using the modefy() function.

> #chaining functions, functions run from left to right on da.df2
> #I am cheating here since you don't know what modify is, 
> #though it is pretty self explanatory.
> da.df3 <- da.df2 %>% select(1, 5:13) %>% filter(species11 > 50) %>% 
+   modify_if(is.numeric, log1p)

A note about pipes: The %>% operator is part of a series of pipes magrittr package. Base R offeres pipes as well |>, however it is slighly less useable than %>%. I still encourage you to try using it.

mutate() has a subset of functions that modify all or a subset of columns from a data frame, negating the need to use a loop.

> #One useful mutate function is mutate_if, it allows to modefy a column if a condition is met
> #For example it allows to change all character columns to factors
> 
> class(df3$Elevation)
[1] "character"
> df3 <- df2 %>% mutate_if(is.character, as.factor)
> class(df3$Elevation)
[1] "factor"
> #mutate_if allows to perform mathematical operations only on numeric columns
> #e.g. log transformation and then multiply by 2 
> #Note that ~ is used to escape the mathematical operator for multiply and the . is used as a placeholder to tell R to run the operation on 
> #the data frame df2.
> 
> df3 <- df2 %>% mutate_if(is.numeric, log1p) %>% 
+   mutate_if(is.numeric, ~.*2)

A note about mutate() and modify() mutate() and modify() are two tidyvers family of functions that can be used to modify columns. Why the redundancy? While the end result might look the same, under the hood they work quite differently. mutate() works by adding columns columns to data frames, if a column exists it rewrites it. modify() on the other hand is designed to be more general and can work on lists as well. It is basically a sort for df[[i]] <- f().

Transforming data frames

The dplyr and tidyr packages have many functions that allow to transform and reshape data frames. Much like base R, dplyr’s bind_rows() and bind_cols() pastes two data frames based on columns or rows. However, dplyr has some functions that allows for more sophisticated joining of two data frames.

> #Let's use df2 and da.df2 as example, one contains information about species

> #How can they be joined? 
>

>
