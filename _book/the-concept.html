Biology 3315 Molecular Evolution and Phylogenetics

The concept

As bioinformaticians you will seldom work alone in your own brilliance. Most likely you will be a part of a team developing tools/analysis pipelines for other scientists, or have to explain your work to peers who are not bioinformaticians. Since we will not be using any new packages, this seems like a good change to develop team working skill to to gain some experience in tool development. During this lab you will work in groups and will write functions designed to analyse population data.

Before you begin solving problems, since these functions will be written with the end user in mind, we will go over ways to catch user input errors and ways to control the flow of a function when a solution is reached.

Catching user input error

Sometimes, despite your best intentions, users will enter values to arguments which will result in your code crushing or will send R in to a tail spin (e.g. vector with negative values when log transforming).

R has a lot of tools for “defensive programming”, I will go over two: stop() and message(). stop(), as its name implies, terminates the execution of the code if a deadly error was identified. In addition it prints an error message.

message(), allows you to print a customized message alerting the user to whatever it is you choose to altrt them about.

Let’s look at how to use stop() and message() to catch user error.

#Let's write a very simple and useless function that takes a numeric vector 
#sums it up and calculate the log of the sum

Log_of_sum <- function(x){
#If the user inputs anything that is not a numeric vector the function will 
#not be able to run properly
#It is possible to test whether the input is in the correct format using an if 
#statement and an is.x function 
  
#If augment x is not numeric stop and print an error message explaining why was
#the execution was stopped
  
  if(!is.numeric(x)){
    stop("x is not a numeric vector")
  }
  
#Remember that matrices are vectors too, therefore is.numeric will result 
#in true for a numeric matrix as well
  
  if(is.matrix(x)){
    
#here we just send the user a message telling them the matrix was coerced to 
#a one dimensional vector
    
    message("x was coerced to a one dimensional vector")
    x <- c(x)
    
  }
  
#as always make sure your function returns a variable
  
  return(los <- log1p((sum(x))))
}

Now - drum roll - let’s use the function and see the magic that is stop.

#First generate a character vector

cv <- letters[1:5]

Log_of_sum(cv)
## Error in Log_of_sum(cv): x is not a numeric vector

Note the error message.

Now lets generate a matrix and get a message that it was coerced to a vector

#Why am I setting seed?
set.seed(1)

#Matrix with 2 columns 
m <- matrix(sample(1:5000,10), ncol = 2)

Log_of_sum(m)
## x was coerced to a one dimensional vector
## [1] 10.2464

Control of flow the break and next functions with-in for loops

Often times, it will be required to run a loop until certain condition (other than the loop condition) is met. However, it is not always known when will this condition be met. For example, when analyzing allele tables you have no way of knowing a-priori at which generation will the population no longer be in equilibrium for a certain allele. The function break() will terminate the operation of a loop once an internal condition is satisfied.

Alternatively, it will be required to skip an iteration step if a certain condition was not met. If we use the previous example, there is no way of knowing a-priori if a population is no longer in HW equilibrium. The function next() will skip iteration steps until a condition is met.

The following code snippet demonstrates how to use break() and next() in a loop, within the context of a function environment. Note that break() will terminate a loop and will exit to a higher level environment. Within a function it will exit to the function environment and not to the global environment.

#Let's write yet another in the long line of simple and useless functions

#This function consists of two loops one prints something until it encounters an element equal to
#to or larger than 100 and the second skips printing something until it encounters an element larger
#than than or equal to 100. 

bn <- function(x) {
  
  #conditional statement to catch input errors
  if(!is.numeric(x)){
    stop("x must be numeric")
  }
  
  #Initializing the counting variable
  
  i=1
  #setting up the loop condition
  #Note that this loop will run first
  for (i in seq_along(x) ) {
    
    #Seting up the break condition 
    if( x[i] < 100) {
      print ("This is loop1")
    } else {
      #Note that break will terminate the loop when encountering the first element that violates
      #the condition. There could be other elements out there.
      print(paste("loop 1 was terminated after",i,"iterations", sep = " "))
      break
    }
    
  }
  
  #Initializing the counting variable for the second loop
  
  i=1
  #Setting up the loop condition
  for (i in seq_along(x)) {
    #Setting up the next condition
    if(x[i]< 100){
      
      #Note that next will skip any element that meets the criterion
      next
    }else{
      #If criterion not met, print something
    print("This is loop2")}
    
  }
  
}
