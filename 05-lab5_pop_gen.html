Catching user input errors

Sometimes, despite your best intentions, users will enter values to arguments that will result in your code crashing or will send R into a tailspin (e.g., a vector with negative values when log transforming).

R has many tools for “defensive programming”. I will go over two: stop() and message(). stop(), as its name implies, terminates the execution of the code if a fatal error is identified. In addition, it prints an error message.

message() allows you to print a message alerting the user to something.

Let’s examine how to use stop() and message() to catch user errors.

# Let's write a very simple and useless function that takes a numeric vector, 
# sums it up, and calculates the log of the sum

Log_of_sum <- function(x){
# If the user inputs anything that is not a numeric vector, the function will 
# not be able to run properly.
# It is possible to test whether the input is in the correct format using an if 
# statement and an is.x function.
  
# If argument x is not numeric, stop and print an error message explaining why
# the execution was stopped
  
  if(!is.numeric(x)){
    stop("x is not a numeric vector")
  }
  
# Remember that matrices are vectors too, therefore is.numeric will result 
# in TRUE for a numeric matrix as well.
  
  if(is.matrix(x)){
    
# Here we send the user a message informing them that the matrix was coerced to 
# a one-dimensional vector
    
    message("x was coerced to a one-dimensional vector")
    x <- c(x)
    
  }
  
# As always, make sure your function returns a variable
  
  return(los <- log1p((sum(x))))
}

Control of flow: the break and next functions within for loops

Often, it will be required to run a loop until a certain condition (other than the loop condition) is met. However, it is not always known when this condition will be met. For example, when analyzing allele frequency tables, you have no way of knowing a priori at which generation the population will no longer be in equilibrium for a certain allele set. The function break() will terminate the operation of a loop once an internal condition is satisfied.

Alternatively, it will be required to skip an iteration step if a certain condition is not met. If we use the previous example, there is no way of knowing a priori if a population is no longer in HW equilibrium. The function next() will skip iteration steps until a condition is met.

The following code snippet demonstrates how to use break() and next() in a loop within the context of a function environment. Note that break will terminate a loop and will exit to a higher-level environment. Within a function, it will exit to the function environment, and outside a function, it will exit to the global environment.

# Let's write another simple function

# This function consists of two loops: one prints something until it encounters an element equal to
# or larger than 100, and the second skips printing something until it encounters an element larger
# than or equal to 100. 

bn <- function(x) {
  
  # Conditional statement to catch input errors
  if(!is.numeric(x)){
    stop("x must be numeric")
  }
  
  # Initializing the counting variable
  
  i=1
  # Setting up the loop condition
  # Note that this loop will run first
  for (i in seq_along(x) ) {
    
    # Setting up the break condition 
    if( x[i] < 100) {
      print ("This is loop1")
    } else {
      # Note that break will terminate the loop when encountering the first element that violates
      # the condition. There could be other elements out there.
      print(paste("loop 1 was terminated after",i,"iterations", sep = " "))
      break
    }
    
  }
  
  # Initializing the counting variable for the second loop
  
  i=1
  # Setting up the loop condition
  for (i in seq_along(x)) {
    # Setting up the next condition
    if(x[i]< 100){
      
      # Note that next will skip any element that meets the criterion
      next
    }else{
      # If criterion not met, print something
      print("This is loop2")
    }
    
  }
  
}

Problem 1

Write a function that tests for Chi-square goodness of fit. The purpose of this function is to be called by the other functions you will write in this assignment, so keep testing for HW equilibrium in mind.

Remember that the formula for Chi-square goodness of fit is:

\[\chi^2 = \sum_{i=1}^{k} \frac{(Obs - Exp)^2}{Exp}\]

Remember that the critical value is used to test the null hypothesis that observed values do not differ significantly from expected values. If your calculated \(\chi^2\) exceeds the critical value, you reject the null hypothesis. The critical value is dependent on the number of categories you sum. This is expressed as degrees of freedom, which is defined as:

\[ df = n-1 \] Where n is the number of categories; in your case, the number of genotypes.

The critical value necessary to reject the null hypothesis can be retrieved using R’s qchisq() function. You can call it within your function.

# Critical value for Chi-square goodness of fit test, the 0.95 percentile with 
# 1 - 3 degrees of freedom
# Note how the function receives the argument; this is the critical value for a p-value equal to or smaller than 
# 0.05, i.e., 5% probability of receiving a larger Chi-square value by chance.

qchisq(0.95, df = 1:3)
[1] 3.841459 5.991465 7.814728

Important: The Chi-square test requires counts (number of individuals), not proportions or frequencies. Your function should be able to handle both types of input and convert frequencies to counts when necessary. Consider adding an argument for population size.

Figure out how many arguments your function will receive (e.g., expected value, observed values, significance level, etc.). What type of variable will each argument accept, and how will you test for correct input by the user? Think about whether you want to assign a default value to any of the arguments.

The function should return a list that stores the following elements at minimum:

  • The significance level

  • The Chi-square value

  • Number of degrees of freedom

  • Whether the null hypothesis is rejected or not

Since you will have to use it in following functions, think about whether you need an element that can be easily accessed by a conditional statement to ask if the null hypothesis was rejected.

At minimum, the function should receive the initial proportion of q, the selection coefficient of the recessive allele, the significance level for the Chi-square test, the number of generations, and the population size.
