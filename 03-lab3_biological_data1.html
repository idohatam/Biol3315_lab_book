5.1 Installing packages from Bioconductor

Bioconductor is a repository that stores R packages geared towards the analysis of biological data. Most packages in Bioconductor are designed to handle omics, cellular, genetic, and biochemical data, and thus will be more useful in more advanced courses. However, some of the packages on Bioconductor are excellent for this course. One of them is the Biostrings package, which, as its name suggests, handles biological strings (i.e., nucleotide and amino acid sequences). While there are packages on CRAN with similar functions, it is a good opportunity to familiarize yourself with the object structure employed by Bioconductor packages.

> # Bioconductor requires its own package manager
> install.packages("BiocManager")
> 
> # Once the manager is installed, you can install Bioconductor packages
> BiocManager::install("Biostrings")
> 
> library(Biostrings)

Note that when you load the packages, functions can get masked. Make sure you are using the function from the correct package. You can do that by specifying the package when calling the function, e.g., dplyr::summarise().


5.2 Working with sequences using base R and the tidyverse

You were introduced to strings during lab 1, and biological strings are no different than regular strings. Nucleotide sequences are comprised of up to 20 nucleotide symbols (ATCG, U, and letters that denote alternative bases, base groups, and modified bases). Amino acid sequences are comprised of up to 28 symbols (the 20 standard amino acids plus special codes for ambiguity and modifications).

Base R and some functions from stringr make it easy to perform basic processing of biological strings. Let’s reexamine a simple example and create a string of 100 nucleotides.

> # Why am I setting seeds?
> set.seed(649)
> # Generate a vector of nucleotides
> sq1 <- paste(sample(c("A","T","C","G"), 100, replace = T), collapse = "")

Next, we can count how many times each nucleotide appears in the sequence using a simple for loop.

> nucs <- c("A","T","C","G")
> reps <- rep(0, 4)
> 
> for (i in seq_along(nucs)) {
+   reps[i] <- str_count(sq1, nucs[i])
+ }
> 
> df <- data.frame(nucs, reps)
> df
  nucs reps
1    A   24
2    T   17
3    C   29
4    G   30

It is also simple to chart these counts.

> ggplot(df, aes(x = nucs, y = reps)) +
+   geom_bar(stat = "identity")

It is relatively simple to find start and stop codons (the first step in predicting ORFs).

> # With the stringr package it is simple to find all start and stop codons
> (atg <- str_locate_all(sq1, "ATG"))
[[1]]
     start end
[1,]     5   7
[2,]    41  43
> # Just one of the stop codons
> (stp <- str_locate_all(sq1, "TAA"))
[[1]]
     start end

From here you can write a loop calculating the length of characters from the first nucleotide of each start codon to the last nucleotide of every stop codon. Those that are divisible by 3 represent open reading frames. We won’t implement this here. The stringr package also makes it easy to convert between DNA and RNA.

> # stringr also makes it easy to convert between DNA and RNA
> sq1.rna <- str_replace_all(sq1, "T", "U")
> 
> str_sub(sq1, 1, 10)
[1] "GAAGATGTCT"
> str_sub(sq1.rna, 1, 10)
[1] "GAAGAUGUCU"

Next, let’s see how to convert a sequence of nucleotides to its reverse and complementary sequence.

> # First let's generate a shorter sequence, it will be easier to inspect
> sq2 <- str_sub(sq1, 1, 10)
> 
> # stringr doesn't have a good option to replace every base with its complement because it can only 
> # replace one pattern at a time.
> sq2c <- str_replace_all(sq2, "T", "A")

Now that all Ts are As, there’s no way to replace all original As with Ts. It can be done by splitting the string into a character vector using str_split from stringr. Note the [[]] since str_split outputs a list.

> sq2c <- str_split(sq2, "")[[1]]
> 
> # Now with a chain of ifelse it is possible to replace each position
> sq2c <- if_else(sq2c == "T", "A",
+                 if_else(sq2c == "A", "T", 
+                         if_else(sq2c == "G", "C", if_else(sq2c == "C", "G", sq2c))))
> 
> # Complementary, indeed.
> sq2
[1] "GAAGATGTCT"
> sq2c
 [1] "C" "T" "T" "C" "T" "A" "C" "A" "G" "A"

We can now use the rev function to reverse the order of the vector, resulting in a sequence that is reverse and complementary.

> sq2
[1] "GAAGATGTCT"
> sq2c
 [1] "C" "T" "T" "C" "T" "A" "C" "A" "G" "A"
> (sq2rc <- rev(sq2c))
 [1] "A" "G" "A" "C" "A" "T" "C" "T" "T" "C"
> # Is it possible to locate a codon using a vector?
> # First occurrence using str_locate
> str_locate(sq2c, "GTT")[1,]
start   end 
   NA    NA

In order to find the codon, we need to find all occurrences of the nucleotide G, and then find which nucleotides are found one and two positions over. Not impossible but definitely annoying. An easier way would be to convert the vector back to a string and match patterns.

Converting a string to its reverse and complement sequence adds a level of complexity because of the switch between strings to character vectors and back. This doesn’t look too complex, but as bioinformaticians you will never work with just one sequence. You will use FASTA files with multiple sequences. Let’s see how base R handles those.

Importing and working with FASTA files

First, what are FASTA files?

FASTA files are text files in the FASTA format. The FASTA format requires that the first line of each sequence be a header, denoted by > (greater than) followed by a description of the sequence, e.g., >E.coli strain K12 complete chromosome. Next are all the letters denoting nucleotides or amino acids with no spaces (basically a string). Sequences in FASTA format are universally used by all sequence repositories, and FASTA files (generally .fa or .fasta extensions, though any txt file with the format will work) are universally used. Because FASTA files are essentially text files, it is easy to import them using the file() and readLines() functions.

> # Let's import 
> nuc_fa <- readLines(
+   file(
+     "https://raw.githubusercontent.com/idohatam/Biol-3315-files/main/practice_nuc.fa",
+     open = "r"))

readLines(file("https://raw.githubusercontent.com/idohatam/Biol-3315-files/main/practice_nuc.fa",
: incomplete final line found on
'https://raw.githubusercontent.com/idohatam/Biol-3315-files/main/practice_nuc.fa'

Now, let’s inspect the file.

> # As can be seen in this example, lines 2-4 still belong to sequence 1

Now that we know the beginning and the end line of each sequence, we can gather some stats. Let’s see how long each sequence is using an elegant for loop.

> # Note: no hard coding. This way, you can reuse this code even if the next file has more sequences.
> seq_length <- rep(0, length(hdr))
> 
> # The for loop
> for (i in seq_along(hdr)) {
+   # What is the role of this if else statement?
+   if(i < length(hdr)){
+     seq_length[i] <- sum(nchar(nuc_fa[(hdr[i]+1):(hdr[i+1]-1)]))
+   } else { 
+       seq_length[i] <- sum(nchar(nuc_fa[(hdr[i]+1):length(nuc_fa)]))
+     }
+ }
> 
> # Let's get the stats on sequence length
> summary(seq_length)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
  544.0   551.0   609.0   655.2   786.0   786.0

We can see that the longest sequence is 786 nucleotides, and the shortest is 544 nucleotides.

What if there is a need to perform more tasks with the sequences? For example, find ORFs, compile the reverse and complementary sequences, or align the sequences against each other, build a phylogenetic tree, etc.?

The fact that the sequences are divided into lines (different elements of a character vector) makes it difficult to process them, and they need to be housed in a new container. Two possible ways to do it are:

  • House them in a dataframe: column 1 will be the header, column 2 will be the concatenated line of each sequence, and column 3 will be the reverse complement sequence.

  • House each of them in a list: the name of each element will be the header, and a second list would be the reverse complement sequence. The two lists could be merged as two nested lists.

Both options will require a fair bit of code. Let’s see what the dataframe option looks like.

> # Let's start with creating 3 vectors
> 
> # Sequence headers
> hdrs <- nuc_fa[hdr]
> 
> # A vector to house the seqs
> sqs <- rep("H", length(hdr))
> 
> # Vector to house the reverse complement seqs
> sqs_rc <- sqs

Now let’s write a for loop to merge all lines of each sequence to one sequence and also produce the reverse complementary sequence.

> for(i in seq_along(hdr)){
+   
+   if(i < length(hdr)){
+     
+     sqs[i] <- paste(nuc_fa[(hdr[i]+1):(hdr[i+1]-1)], collapse = "")
+     
+     # My function also makes sure to check if the string is split or not and splits it if needed.
+     sqs_rc[i] <- rev_comp(sqs[i])
+     
+   } else{
+     
+     sqs[i] <- paste(nuc_fa[(hdr[i]+1):length(nuc_fa)], collapse = "")
+     
+     sqs_rc[i] <- rev_comp(sqs[i])
+     
+   }
+ }
> 
> # Now let's bind the vectors as dataframe
> df_sqs <- data.frame(hdrs, sqs, sqs_rc, stringsAsFactors = F)

Now that the sequences are housed in a dataframe, it is easy to get what we need from them.

> # Calculate
> df_sqs <- df_sqs %>% mutate(Seq.len = nchar(sqs))
> 
> # Get sequence stats
> summary(df_sqs$Seq.len)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
  544.0   551.0   609.0   655.2   786.0   786.0 
> # Get all ATGs
> ATGs <- str_locate_all(df_sqs$sqs, "ATG")
> # Result is a list with 5 elements, each with the positions of ATG of a particular sequence
> # This is for the first sequence
> ATGs[[1]]
     start end
[1,]    92  94
[2,]   148 150
[3,]   317 319
[4,]   386 388
[5,]   467 469
[6,]   543 545

Because dataframes require that all columns be of the same length, they are not very flexible and only allow you to work with strings. The second option, working with lists, affords more flexibility since each element of the list is independent of each other and can even be another list. Therefore, you could generate a set of nested lists where the outer list will house all other lists, and each nested list will contain the string and vectorized sequences.

Example:

List of sequence 1 (element one (string of sequence), element two (string of reverse complement), element 3 (character vector of sequence), element 4 (character vector of reverse complement)) . . . List of sequence 5 (….) )

From there you can add more elements such as location of all ORFs, corresponding RNA and amino acid sequences. However, as you can see, all these will require a lot of coding! Luckily you don’t have to reinvent the wheel since there are a few R packages designed to handle biological strings. This, however, was not a pointless exercise because you gained an understanding of some of the data structures generated by these packages, and hopefully it will make it easier for you to work with them. Furthermore, now you know what it takes to write a package like the ones you will use. This understanding will serve you when you will be required to develop your own packages when you work as a bioinformatician.


5.3 Biostrings

The first package we’ll work with is Biostrings. As its name suggests, this is a package that handles biological strings. It can handle DNA, RNA, and amino acid sequences and is also capable of pattern matching, which helps with sequence look-up and alignment (albeit limited in that respect). Biostrings allows you to import individual sequences or FASTA files containing multiple sequences.

Biostrings uses a specialized container class called XString to store sequences. XString is similar to a character vector; however, unlike a vector, it can only house a single string.

The XString class has four subclasses:

  1. DNAString - stores DNA sequences

  2. RNAString - stores RNA sequences

  3. AAString - stores amino acid sequences

  4. BString - stores general strings

Let’s look at a few examples of working with strings using Biostrings.

> # As always, let's generate a random string and convert it to an XString object
> string <- "This is a random string (is it random though?!)"
> 
> # Now let's call it as DNAString
> string <- DNAString(string)
Error in `.Call2()`:
! key 105 (char 'i') not in lookup table

Uh-oh, an error message. This is because DNAString is limited in which characters it accepts. Remember, only BString is character-agnostic.

Let’s see which characters DNAString accepts.

> DNA_ALPHABET

> # In case you were wondering what each of those letters mean, Biostrings has a function with the 
> # details. Useful when designing synthetic sequences like primers
> 
> IUPAC_CODE_MAP
     A      C      G      T      M      R      W      S      Y      K      V 
   "A"    "C"    "G"    "T"   "AC"   "AG"   "AT"   "CG"   "CT"   "GT"  "ACG" 
     H      D      B      N 
 "ACT"  "AGT"  "CGT" "ACGT"

As you can see, DNAString accepts more than just ATCG. It also accepts base categories, strand orientation (+/-), and alignment gaps.

Let’s see which characters the other two restricted subclasses accept.

One advantage of the XString class is that it allows you to treat the sequence both as a vector and as a string, making it easy to index, subset, and modify.

The code snippet below demonstrates how to access and modify an XString class object.

> # Let's get the first element of the AA sequence
> casein[1]
1-letter AAString object
seq: P
> # Let's subset
> casein[1:5]
5-letter AAString object
seq: PYFNI
> # Another great feature of the XString class is that the string is mutable in the same way a vector 
> # is. Let's change the first AA to methionine.
> 
> casein[1] <- "M"
> 
> # Appending characters is done in the same way you would a character vector.
> casein[11] <- "J"
> # Reminder that gaps can also be added.
> casein[10] <- "-"

Because XString class objects are treated as strings, it is easy to use functions from base R to process them. Let’s use grepl(), which works like str_detect for pattern matching. Note that I am calling base:: because grepl is masked by BiocGenerics, a Bioconductor package. It will work the same if you choose to use the BiocGenerics function.

> base::grepl("MYFNI", casein)
[1] TRUE

tidyverse packages are more particular about the data types they accept and require some manipulation. I used the base R function toString() to turn casein into… a string.

> str_detect(toString(casein), "MYFNI")
[1] TRUE

It is also possible to use base R functions like gsub() and stringr functions like str_replace() to edit casein; however, it takes a bit of tinkering to keep it as an XString element. Still, it is worthwhile if editing chunks of sequence. Note that here I am also introducing you to base R’s native pipe operator |>. We won’t use it often, but it’s worth knowing.

> # tidyverse
> casein2 <- casein %>% toString %>% str_replace("MYFNI", "MYXGT") %>% AAString()
> 
> # base R with the native pipe
> casein3 <- gsub("MYFNI", "MYXGT", casein) |> AAString()

Working with multiple sequences

As you know by now, bioinformaticians do not work with a single sequence but rather with many sequences in parallel. Biostrings offers the class XStringSet as a container for multiple sequences. Here too, it is a combination of a list and a vector. Think of it as a list of XString class objects.

Just like with the XString, the XStringSet offers four subclasses:

  1. DNAStringSet to house DNA sequences

  2. RNAStringSet to house RNA sequences

  3. AAStringSet to house amino acid sequences

  4. BStringSet to house sets of diverse strings

This means that a BStringSet can house the DNA, RNA, and AA sequences of a particular gene.

Let’s see what it looks like.

While seqinr does not seem impressive compared to Biostrings, it does have some perks. One of them is the ability to download sequences straight from releases of online databases such as GenBank and EMBL stored on servers of the University of Lyon in France. It’s worth noting that it is not the only package that can do that. ape is another package that can do that, and you will be introduced to it in lab #4.

First, let’s inspect which sequence repositories seqinr can interface with.

> # Getting the list of repositories
> # Note, to prevent masking, the code specifies to use choosebank from the seqinr package
> 
> repos <- seqinr::choosebank()
> # Large list 
> repos

In order to download sequences from a database, you must first select it using the choosebank() function. Here we will work with genbank, a comprehensive publicly available database of genetic sequences maintained by the NIH.

> # Chooses genbank
> bank <- seqinr::choosebank(bank = "genbank", infobank = T)
> 
> # Let's inspect the database
> bank

As you can see, unfortunately the university works with a release that isn’t very up-to-date. Next, let’s download some sequences. Since genbank is a massive repository with tens, if not hundreds, of GB of data, let’s be targeted and download only sequences associated with the bacterium Escherichia coli.

To download the sequences, we will use the query function. The listname argument names your list, and the query argument tells the function which sequences to download. FYI 1: the query argument accepts regular expressions, which can simplify things. FYI 2: having an argument with an identical name to the function is not great practice.

> ecoliq <- seqinr::query(listname = "ecoli", query = "sp=Escherichia coli")

Now let’s see how many sequences associated with E. coli are in our database, and download the first 10 with the function getSequence. Note the query outputs the sequences as a list. That’s why we need to use the function unlist to get a character vector.

> # See how many seqs
> length(ecoliq$req)
> 
> ecoli10 <- unlist(getSequence(ecoliq$req[1:10], as.string = TRUE))
> 
> # Can treat individual elements as strings
> # Get the first 10 characters of the first sequence.
> substring(ecoli10[1], 1, 10)

As you can see, downloading sequences using seqinr stores the information in very basic containers. The next step will be to convert them to an XStringSet object.

> # DNAStringSet accepts vectors with strings as elements. That's why we used unlist in the previous 
> # step
> ecoli10dss <- DNAStringSet(ecoli10)
> 
> # Let's add the sequences' names to the XStringSet object.
> # This is a nifty trick using lapply in lieu of a for loop.
> # The [[ part tells lapply to use square brackets to subset each element of the list, and the 1 
> # tells it what position.
> # Unlist turns the subset list into a vector that can then be used for the names function 
> 
> names(ecoli10dss) <- unlist(lapply(ecoliq$req[1:10], '[[', 1))

5.5 Exporting sequence elements

Now that we got all of these sequences into R, how do we get them out? As always, there are several options.

Let’s start with the easiest option: writing a file using Biostrings.

> # writeXStringSet exports XStringSets as FASTA files 
> # When you open the file you will notice that the name of each sequence is now the header 
> writeXStringSet(ecoli10dss, "ecoli1.fa")

seqinr also allows you to export objects as FASTA files.

> # write.fasta is a seqinr function to save objects as FASTA files
> write.fasta(sequences = fa.snr, names = names(fa.snr), file.out = "practice2.fa")

Lastly, base R write function allows you to also write FASTA files (since they are basically text files). Not as elegant since it requires a loop, which really slows down the operation.

> i = 1
> 
> for (i in seq_along(ecoli10dss)) {
+   # This part writes the header
+   write(paste(">", names(ecoli10dss[i]), sep = ""), file = "ecoli2.fa", append = T)
+   # This part writes the sequence
+   write(paste0(ecoli10dss[i]), file = "ecoli2.fa", append = T)
+ }
